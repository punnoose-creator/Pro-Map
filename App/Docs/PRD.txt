# 📄 Product Requirements Document (PRD)

## Product Name: **Pro Map**

---

# 1. 🎯 Product Overview

**Pro Map** is an employee tracking and work logging system that enables organizations to:

* Track employee location during work hours
* Collect real-time work updates (text + voice input)
* Provide admins with visibility via maps and reports
* Generate automated summaries (weekly/monthly)

---

# 2. 🧩 Problem Statement

Organizations with field employees lack:

* Real-time visibility of employee location
* Structured work reporting
* Easy-to-analyze productivity data

Existing solutions are either:

* Too complex
* Too expensive
* Not optimized for lightweight usage

---

# 3. 🎯 Goals & Objectives

### Primary Goals

* Enable accurate employee location tracking during work hours
* Simplify work reporting via voice + text
* Provide actionable insights to admins

### Success Metrics

* Daily Active Users (DAU)
* % of employees starting work sessions
* Average work logs per employee per day
* Admin engagement (dashboard usage)
* Summary generation usage rate

---

# 4. 👤 User Roles

## 1. Employee

* Logs in
* Starts/stops work tracking
* Adds work updates
* Logs out

## 2. Admin

* Logs in
* Views employee dashboard
* Tracks employee movement on map
* Reads work logs
* Downloads summaries

---

# 5. 📱 Features & Functional Requirements

---

## 5.1 Employee App

### 5.1.1 Login

* Email/Username + Password authentication
* Secure session (JWT/token-based)
* Option to login as Admin

---

### 5.1.2 Home Screen

#### Buttons:

1. **Start Work**
2. **Add Work**
3. **Logout**

---

### 5.1.3 Start Work

#### Flow:

* Request permissions:

  * Location (foreground + background)
* Start **foreground service**
* Capture location every 5–10 minutes
* Store data locally if offline
* Sync with backend when online

#### UI:

* Show “Work Active” status
* Show timer (optional)
* Provide **Stop Work button**

---

### 5.1.4 Stop Work

* Stops location tracking service
* Ends work session

---

### 5.1.5 Add Work

#### UI Elements:

* Text input field
* "Speak" button (voice-to-text)
* "Submit" button

#### Flow:

1. User clicks “Speak”
2. App requests microphone permission
3. Converts speech → text
4. User edits text (optional)
5. On submit:

   * Capture timestamp
   * Capture current location
   * Send to backend

---

### 5.1.6 Logout

* Ends session
* Stops tracking if active

---

## 5.2 Admin Dashboard

(Recommended: Web app for scalability)

---

### 5.2.1 Dashboard Overview

* List of employees
* Status:

  * Active / Inactive
* Last known location
* Last activity timestamp

---

### 5.2.2 Employee Detail View

#### Map Section:

* Display location markers (every 5 min)
* Show movement path (polyline)
* Zoom & pan controls

#### Work Logs Section:

* Chronological list of entries
* Each entry includes:

  * Text update
  * Timestamp

#### Interaction:

* Clicking a log:

  * Highlights corresponding location on map

---

### 5.2.3 Summary Generation

#### Options:

* Weekly Summary
* Monthly Summary

#### Functionality:

* Uses LLM in backend
* Summarizes:

  * Movement patterns
  * Work logs

#### Output:

* Downloadable (PDF/CSV)

---

# 6. 🧠 Non-Functional Requirements

---

## 6.1 Performance

* Location updates should not exceed battery limits
* API response time < 500ms

---

## 6.2 Scalability

* Support 1,000+ concurrent users
* Efficient storage of location data

---

## 6.3 Reliability

* Offline data storage (local caching)
* Retry failed API calls

---

## 6.4 Security

* Encrypted API communication (HTTPS)
* Secure authentication (JWT)
* Role-based access (Employee/Admin)

---

## 6.5 Privacy & Compliance

* Explicit user consent for tracking
* Ability to stop tracking anytime
* Privacy policy required
* Data encryption at rest

---

## 6.6 Battery Optimization

* Use balanced location accuracy
* Adaptive tracking interval
